# AuditCore — Security Reference

## Secrets & where they live

All secrets are in `.env` (chmod 600, **never** committed — it's in
`.gitignore`). Generated by `install.sh`:

| Variable | Purpose |
|---|---|
| `ENCRYPTION_MASTER_KEY` | Root key for file-at-rest encryption (per-file keys derived via HKDF). **If lost, encrypted uploads are unrecoverable.** |
| `JWT_SECRET` / `SECRET_KEY` | App signing (download tokens, HMAC, internal). |
| `SUPABASE_JWT_SECRET` | Verifies Supabase login tokens (HS256 legacy; ES256 tokens verified via JWKS). |
| `SUPABASE_SERVICE_ROLE_KEY` | Admin API (user creation in seed). **Full DB power — protect it.** |
| `REDIS_PASSWORD`, `POSTGRES_PASSWORD` | Generated for on-prem/local use. |

## Encryption

- **Files at rest:** AES-256-GCM. Each uploaded file gets a unique key derived
  with **HKDF-SHA256** from `ENCRYPTION_MASTER_KEY` + `company_id` + file UUID.
  Keys are never written to disk or DB. On-disk blobs begin with magic `AGEC1`.
- **Backups:** AES-256-CBC (OpenSSL, PBKDF2) using `ENCRYPTION_MASTER_KEY`.
- **Decryption** happens only in memory (OCR, image display, exports).

## Row-Level Security (RLS) — Zero-Knowledge for auditors

Analytics, waste map, risk alerts, cross-reference findings, notifications, and
daily digests are **hidden from the `auditor` role** at the database level.

The app calls `SELECT set_user_role('<role>')` on every request (see
`app/api/deps.py`). Policies use
`current_setting('app.current_user_role', true) IS DISTINCT FROM 'auditor'`.

> **Critical:** RLS is bypassed by Postgres **superusers** and roles with
> **BYPASSRLS** (Supabase's `postgres` role has `BYPASSRLS`). The runtime app
> must connect as a **non-privileged role** for RLS to actually apply. Verify:

```bash
# Confirm the connecting role is NOT bypassing RLS
docker compose exec backend python - <<'PY'
import asyncio
from sqlalchemy import text
from app.database import engine
async def main():
    async with engine.connect() as c:
        r=await c.execute(text("select current_user, "
          "(select rolbypassrls from pg_roles where rolname=current_user)"))
        print(r.first())
asyncio.run(main())
PY
```

### Verify auditor isolation directly
```bash
docker compose exec backend python - <<'PY'
import asyncio
from sqlalchemy import text
from app.database import AsyncSessionLocal
async def main():
    async with AsyncSessionLocal() as s:
        await s.execute(text("select set_user_role('auditor')"))
        n=(await s.execute(text("select count(*) from waste_map_items"))).scalar()
        print("auditor sees waste rows:", n, "(must be 0)")
        await s.execute(text("select set_user_role('owner')"))
        n=(await s.execute(text("select count(*) from waste_map_items"))).scalar()
        print("owner sees waste rows:", n)
asyncio.run(main())
PY
```

## Tamper-proof audit ledger

Every critical action is appended to `audit_ledger` as a SHA-256 hash chain
(`current_hash = SHA256(previous_hash + canonical(entry))`). Verify integrity:

```bash
curl -H "Authorization: Bearer <OWNER_TOKEN>" http://localhost:8000/owner/ledger/verify
# => {"is_valid": true, "total_entries": N, "broken_links": []}
```
Exports embed a tamper-proof certificate (last ledger hash + HMAC over content).

## Key rotation

> Rotating `ENCRYPTION_MASTER_KEY` makes **existing** encrypted files/backups
> unreadable. Only rotate with a re-encryption migration. Procedure:

1. Take a full backup (`./backup.sh`) and verify it.
2. For file keys: run a re-encryption job (decrypt with old key, re-encrypt with
   new) — contact the App Owner for the migration script before rotating.
3. `JWT_SECRET` / `SECRET_KEY` / Supabase keys can be rotated freely (invalidates
   active sessions / signed download URLs). Update `.env` and
   `docker compose up -d` to apply.
4. After any secret appears in logs/chat, **rotate it** in Supabase
   (Settings → API) and re-run the relevant part of install.

## Network hardening

- PostgreSQL/Redis are **not published** to the host (Docker-internal only).
- Backend container runs as a **non-root** user (`appuser`, uid 10001).
- Put the box behind a reverse proxy with TLS for any external access.

## Pending hardening (roadmap)

  these are configured in **Supabase Auth settings** (rate limits) + a frontend
